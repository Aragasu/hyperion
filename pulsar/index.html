Start here · the essentials

Five things every server actually needs.

A community can run on five features: one trap channel for the raids, games people actually play, levels worth climbing, coins worth spending, and the utility commands you would otherwise keep a browser tab open for.

Honeypot

A trap channel. Put it where a spam bot or a raider will find it, tell your members to stay out, and leave it empty on purpose. Everything posted in it is deleted, and the account behind it is dealt with before your chat ever sees the spam.

  • The message is removed on sight
  • Punishment is yours: kick, ban, timeout or report only
  • Staff get an alert naming the account and what was done
  • Only the server owner can arm it
Arm it in four lines
p!honeypot channel #honeypotThe channel nobody should post in
p!honeypot action kickkick (default) · ban · timeout 60 · none
p!honeypot alerts #staffWhere the catch report lands
p!honeypot catchesThe ten most recent, newest first

A timeout takes minutes, up to seven days. delete and notify control the cleanup and the DM. Both stay on unless you turn them off.

Honeypot · a step by step explanation

Someone posts. Five things happen.

This is the order the bot works in.

  1. 01
    It is written down first

    The catch is recorded before anything else is even attempted: who they are, what they typed, when, and what this server chose to do about it.

    One entry, patched with the outcome afterwards rather than a second line underneath it. A log that lists the same intrusion twice, once as unknown and once as handled, is worse than either.

  2. 02
    The message goes

    Deleted, because a trap that leaves the spam sitting in the channel has not done anything about the spam.

  3. 03
    The punishment fires

    Whatever you chose with p!honeypot action. A kick is the default: somebody in a channel called honeypot is not there by accident, but they are usually a bot or a spammer rather than somebody who deserves a permanent ban for one message. Ban and timeout are there to be picked deliberately. A timeout runs for as many minutes as you set, up to a week.

    Report only is another option: the message still goes, nothing happens to the poster, and a human decides the rest.

  4. 04
    They are told why

    One direct message: that they posted in a channel which only exists to catch spam, what happened to them, and to ask a human if that came as a surprise.

    It goes after the punishment on purpose. Once somebody is kicked or banned there is no shared server left to send it through, which makes it best-effort by nature rather than by choice. A kick with no explanation is how somebody spends an afternoon convinced the server is broken.

  5. 05
    Staff get the alert

    Into the channel you named, or into the trap itself if you never named one. It quotes what they typed as plain text, and it says what was actually done, not what was intended.

    If a step failed, the alert says so and names the permission that is probably missing.

And the log it leaves, p!honeypot catches
@spammer — totallynotascamwebsite.com✅ handled · 2 minutes ago
@raidbot — a✅ handled · 6 hours ago
@tourist — hi🚨 reported · yesterday

The ten most recent are shown, newest first; only the newest 20 are kept. Each line ends in what happened to that catch: handled, not handled, or reported only.

Who never lands in the trap
  • The server owner
  • Pulsar itself
  • Everyone in every other channel, and everyone at all while the trap is off

A command typed into the trap is punished and never answered. The trap does not chat back. Silence in the channel is the point; the alert is the only output.

What it asks of you
  • A role for Pulsar above the people it acts on, with Manage messages and the matching Kick, Ban or Timeout members
  • A channel everyone can see on join.
  • The server owner to arm it: not administrators and not a role, because this is one decision to act on whoever posts, so one person answers for it
  • Nothing beyond Manage messages if you set it to report only

Failures close rather than open: if Pulsar cannot read who owns the server, it will not arm a trap on your word alone. And picking the trap channel switches it on. p!honeypot off takes it back off.

Tickets are real channels

Each ticket is a private channel in a Tickets category, open to whoever asked, the staff roles and Pulsar. A panel card can carry up to ten categories — Support, Applications, Reports — and nobody has to learn the command. A member of staff claims a ticket; closing writes an HTML transcript, and a quiet one closes itself.

  • p!ticket panel #support
  • Open, close, reopen, delete
  • Claim it, so two staff do not answer at once
  • An HTML transcript when it closes
  • Auto-close after a set silence
  • The opener gets a DM

Reaction roles

Set up a panel, add a role per emoji, and reacting hands it out. Un-reacting takes it back. The panel is edited in place as you add roles, so the list on screen is always current.

Giveaways that survive

p!giveaway start 10m A prize posts the entry, draws on a timer and can reroll. Entries and the deadline live on disk, so a restart mid-giveaway does not wipe them.

Coins & levels

A global wallet with daily streaks, work, beg, pay, rob, slots, roulette and blackjack. Ordinary messages earn XP; p!rank shows the climb and p!levels the leaderboard.

Each one lives in the channel it started in, so two can run side by side, and each can be stopped by name. Trivia has 40 questions and a global scoreboard.

Automod & honeypots

Eight automod rules — mass mentions, invite links, mention floods, repeats (near-duplicates included), emoji floods, text spam, caps and the link filter, which sees through lookalike domains (d1scord.com), adult hosts, shorteners and raw IPs. Report by default, or delete and timeout on request. p!mediascan checks attachments too: a program wearing a photo.png.exe name, or a file named after something it is not. A honeypot is a trap channel: post in it and the message goes, then the poster gets whatever you chose.

  • p!honeypot action kick | ban | timeout 60 | none
  • Only the server owner arms a honeypot
  • Staff are told who, and what was done
  • p!automod links allow add example.com/docs
  • p!mediascan on · p!mediascan action delete

Under the hood

Built to be trusted with the keys.

A bot that can ban people has to be careful about who it listens to. These are the decisions that shaped the rest of it.

01 · Permissions
It checks the caller, then itself.

Every moderation command asks Yapper what the person who typed it is allowed to do, ban_members for p!ban, manage_messages for p!clear, manage_nicknames for p!nickname. The action then runs with Pulsar's own roles, exactly as it would for a person.

If the roles cannot be read, the answer is "I could not check" and nothing happens. Failing open would hand p!ban to anyone who can type it.

Give Pulsar a role above the ones it should manage. Without one it can read, post, react and DM. And nothing else.

02 · State
A restart is not a reset.

Giveaways, polls, reminders, tags, warnings, the greeter's settings, the counting high score and everyone's daily streak all outlive a restart of the bot. A giveaway that forgets its entries the moment the process cycles is worse than no giveaway at all.

So a week-long reminder still arrives, yesterday's giveaway still draws its winner, and nobody loses a streak because the bot blinked. None of that asks you to run a database.

03 · Footprint
Nothing for you to install.

Pulsar runs for you. There is no container to deploy, no configuration file to fill in and nothing on your side to keep patched. You add it, give it a role, and type p!help. That is the entire footprint.

The math command's evaluator is a real tokenizer and parser rather than eval, because the input is whatever a stranger types into somebody else's server. Decisions like that are why it can be handed a moderator's power at all.

Take it with you

Add Pulsar to your server.

No invite link. A server manager adds Pulsar by its code in two taps, then gives it a role so it can do its job.

  1. 01
    Copy the bot code
    The card beside this holds it. It's also what p!invite prints, so you never have to hunt for it.
  2. 02
    Add it from server settings
    Server settings → Bots → Your bots → Add, then paste the code. Once Pulsar is on the public list it will also be under Community bots.
  3. 03
    Say hello
    Type p!help for all command categories in one message, p!help {command} for one, or /help from the slash menu.
  4. 04
    Give it a role
    Kick, pin, bulk delete and ticket channels all need the bot's own permissions. Add a role with those and put it above the roles it manages. Without one it can read, post, react and DM. Nothing else.
